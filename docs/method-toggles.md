# Условное выполнение методов

`featurify-grpc-starter` предоставляет аннотации в пакете
`ru.a1pha1337.featurify.client.annotation`. Они работают на методах Spring beans.
Java-код аннотаций и инфраструктуры компилируется с `--release 8` против Spring 5.0 /
Boot 2.0. Версии Spring в приложении определяет его собственный BOM. AspectJ,
Kotlin runtime и серверные модули для обработки аннотаций не нужны.

| Аннотация | Обязательные параметры | Условие выполнения |
| --- | --- | --- |
| `BooleanFeatureToggle` | `name` | Boolean-значение равно `hasValue` (по умолчанию `true`) |
| `EnumFeatureToggle` | `name`, `hasValue` | Строки совпадают точно, с учётом регистра |
| `VectorFeatureToggle` | `name`, `element` | Состояние элемента равно `hasValue` (по умолчанию `true`) |

```java
import org.springframework.stereotype.Service;
import ru.a1pha1337.featurify.client.annotation.BooleanFeatureToggle;
import ru.a1pha1337.featurify.client.annotation.EnumFeatureToggle;
import ru.a1pha1337.featurify.client.annotation.VectorFeatureToggle;

@Service
public class Notifications {
    @BooleanFeatureToggle(name = "feature1", hasValue = true)
    public void sendNotification() {
        // Побочные эффекты выполняются только при совпадении условия.
    }

    @EnumFeatureToggle(name = "provider", hasValue = "STRIPE", group = "checkout")
    public void processPayment() {
        // Точное сравнение ENUM со строкой STRIPE.
    }

    @VectorFeatureToggle(name = "channels", element = "EMAIL")
    public void sendEmail() {
        // Проверяется состояние EMAIL, а не только его наличие.
    }
}
```

## Контракт вызова

При каждом вызове через proxy общий `FeatureToggleAdvisor` выбирает соответствующий
`BooleanFeatureService`, `EnumFeatureService` или `VectorFeatureService`. При совпадении
значения выполняется исходный метод с исходными аргументами. Иначе тело метода не
выполняется, управление возвращается вызывающему коду.

Аннотации поддерживают только публичные, нестатические, не `final` методы с JVM-типом
результата `void`, включая обычные Kotlin-функции с результатом `Unit`.
Возвращающие значения методы, `suspend`, `Future`, `Mono` и `Flux` не поддерживаются.
Для PAYLOAD нет универсального условия выполнения; используйте явную проверку через
`PayloadFeatureService`.

Исключения gRPC, включая `NOT_FOUND`, `FAILED_PRECONDITION`, `UNAUTHENTICATED` и
`UNAVAILABLE`, передаются без изменения вместе с trailers; метод при этом не выполняется.
Отсутствующая фича или отсутствующий элемент VECTOR считаются ошибкой, а не выключенным
значением. Исключения самого метода также передаются без изменения.

## Группы, namespace и кеш

У всех аннотаций есть параметр `group`:

- Параметр не указан: используется перегрузка сервиса без группы и его default group
  (`featurify.grpc.default-group` для стандартных сервисов).
- `group = ""`: явное обращение к Global, даже если настроена другая default group.
- Непустой ключ: обращение к указанной группе.

Различие между неуказанной группой и Global задаёт константа
`FeatureToggleGroups.DEFAULT`; передавать её вручную не требуется.
Namespace определяется токеном используемого клиента. Аннотации не меняют токен или namespace.

Значения читаются через существующие сервисные кеши: TTL по умолчанию `1s`,
`featurify.grpc.cache.ttl=0s` отключает кеширование. После истечения TTL следующий вызов
синхронно загружает значение. RPC-ошибки не кешируются. Метаданные аннотаций кешируются
отдельно от значений и не фиксируют состояние фичи при запуске.
Собственные beans сервисов, заменяющие стандартные, используются и аннотациями.

## Проверка деклараций и ограничения proxy

Декларации проверяются при инициализации bean, для обычных singleton beans — при запуске.
Lazy/prototype beans проверяются при их создании. Проверка не обращается к gRPC-серверу.
Пустое имя фичи, группа из пробелов, пустой/слишком длинный элемент VECTOR, неподдерживаемая
сигнатура и несколько разных toggle-аннотаций на одном методе вызывают понятную ошибку.
Удалённое существование фичи и её тип проверяются только при вызове.

Аннотация может находиться на методе реализации или интерфейса; поддерживаются generic
интерфейсы и bridge-методы. Аннотация того же типа на реализации имеет приоритет перед
интерфейсом. Разные типы аннотаций на реализации и соответствующем методе интерфейса
считаются конфликтом.

Инфраструктура регистрируется автоматически вместе с gRPC-автоконфигурацией через общий
Spring auto-proxy creator. Дополнительные `@EnableAspectJAutoProxy` и AOP starter не нужны.
По умолчанию используются class proxies; `spring.aop.proxy-target-class=false` выбирает
JDK-прокси для beans с интерфейсами. Настройки других механизмов Spring могут принудительно
включить class proxies. При class proxy класс должен быть не `final`; при JDK proxy
аннотированный метод должен быть доступен через интерфейс. Для Kotlin используйте
`kotlin-spring` на `@Service`/`@Component` или явно объявляйте класс и методы `open`.

Вызовы через `this`, вызовы из конструктора/инициализации и вызовы на объектах, созданных
вручную, не проходят через proxy. Выносите защищаемые операции в отдельный Spring bean
и вызывайте через внедрённую зависимость. Аннотации не заменяют авторизацию.

`featurify.grpc.enabled=false` отключает клиент, стандартные сервисы и обработку
toggle-аннотаций. В этом режиме аннотации не ограничивают выполнение методов.
`spring.aop.auto=false` управляет стандартной Boot AOP-автоконфигурацией и не отключает
собственный advisor Featurify.

## Транзакции и асинхронность

Advisor имеет порядок `Ordered.LOWEST_PRECEDENCE - 100`, поэтому проверка выполняется
до стандартного `@Transactional` advisor: пропущенный метод не открывает транзакцию.
Уже открытая вызывающим кодом транзакция сохраняется. Если приложение меняет порядок
transaction/security/cache advisors, оно должно согласовать его с этим порядком.

При стандартном `@Async` проверка выполняется в рабочем потоке до тела метода. Постановка
задачи в executor не предотвращается. Ошибки проверки для async `void` обрабатываются
обычным `AsyncUncaughtExceptionHandler`, как и другие ошибки асинхронного метода.

## Проверки совместимости

`verifyClientCompatibility` проверяет опубликованные Maven JAR в независимых приложениях
на Boot 2.0.9, 2.6.15, 2.7.18 (Java 8), 3.5.16 (Java 21) и 4.1.1 (Java 25).
Проверяются три типа аннотаций, JDK/CGLIB proxy, interface/implementation/generic методы,
группы, передача ошибок и отказ запуска при некорректной сигнатуре.
Тесты starter дополнительно проверяют кеш, пользовательские сервисы, аргументы,
валидацию деклараций, транзакции и async.
